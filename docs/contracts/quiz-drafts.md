# Private quiz drafts

Issues [#47](https://github.com/CusmaLinux/robinhoot/issues/47) and [#48](https://github.com/CusmaLinux/robinhoot/issues/48), OpenSpec `add-quiz-authoring` tasks 2.1–3.4. Implemented: create/list/read, atomic edits, stable identities, question/option ordering, and multiple-choice readiness. Deletion and final stage handoff remain in [#49](https://github.com/CusmaLinux/robinhoot/issues/49).

## Authentication and ownership

All routes require `Authorization: Bearer <accessToken>` from the existing [account API](authentication.md). Credentials expire after fifteen minutes and remain subject to account/token-version checks. No additional role is required. Ownership comes exclusively from the verified identity; an admin receives no access to another owner's quiz.

No request accepts `ownerId`, account roles, quiz IDs, timestamps, or readiness. POST accepts only the optional title; PUT also accepts the complete ordered question collection with client-generated question/option IDs. Unknown fields receive 400 rather than being silently ignored. Responses exclude owner identity and account details.

## Create

`POST /quizzes` accepts an optional JSON object. `{}` (or an omitted body) creates an empty draft. The only supported property is `title`, an optional string of at most 200 characters. `null`, nonstrings, and longer titles receive 400. Blank and whitespace-only titles are valid saved drafts but are not ready to host. Text is preserved as submitted.

```json
{}
```

HTTP 201:

```json
{
  "id": "d65ae15c-a1d9-42ce-a328-104d2eebd8f1",
  "title": "",
  "questions": [],
  "createdAt": "2026-10-24T00:00:00.000Z",
  "updatedAt": "2026-10-24T00:00:00.000Z",
  "hostable": false,
  "errors": [
    { "field": "title", "code": "REQUIRED", "message": "Title is required" },
    {
      "field": "questions",
      "code": "QUESTION_COUNT",
      "message": "Quiz must contain 1–20 questions"
    }
  ]
}
```

Alternatively, send `{ "title": "Biology" }`. The saved response has that title and only the `questions` readiness error. Every newly created draft starts with zero questions, so `hostable` is false. Readiness errors describe incomplete saved content, not a failed save. A readiness check does not return 400 or prevent persistence.

Quiz IDs are generated by PostgreSQL. Timestamps are UTC ISO 8601 strings and are equal at creation. A create response is sent only after insertion succeeds. Repeating POST creates another draft; it is not an idempotent update.

## Save and reorder

`PUT /quizzes/{id}` requires a JSON object with both `title` and `questions`. It replaces all editable content in one atomic, owner-scoped database update; omitted questions/options are removed. It does not create a missing quiz. A successful save returns HTTP 200 with saved content and derived readiness, even for incomplete content. `createdAt` stays fixed; `updatedAt` is the database write time. Repeated saves preserve the submitted content and IDs while updating `updatedAt`. Concurrent saves use last-write-wins semantics; this endpoint has no revision/conflict detection.

```json
{
  "title": "Biology",
  "questions": [
    {
      "id": "10000000-0000-4000-8000-000000000001",
      "type": "multiple-choice",
      "prompt": "Which cell contains a nucleus?",
      "options": [
        {
          "id": "20000000-0000-4000-8000-000000000001",
          "text": "Animal"
        },
        {
          "id": "20000000-0000-4000-8000-000000000002",
          "text": "Bacterium"
        },
        {
          "id": "20000000-0000-4000-8000-000000000003",
          "text": "Virus"
        },
        {
          "id": "20000000-0000-4000-8000-000000000004",
          "text": "None"
        }
      ],
      "correctOptionIds": ["20000000-0000-4000-8000-000000000001"],
      "durationSeconds": 20
    }
  ]
}
```

HTTP 200:

```json
{
  "id": "d65ae15c-a1d9-42ce-a328-104d2eebd8f1",
  "title": "Biology",
  "questions": [
    {
      "id": "10000000-0000-4000-8000-000000000001",
      "type": "multiple-choice",
      "prompt": "Which cell contains a nucleus?",
      "options": [
        {
          "id": "20000000-0000-4000-8000-000000000001",
          "text": "Animal"
        },
        {
          "id": "20000000-0000-4000-8000-000000000002",
          "text": "Bacterium"
        },
        {
          "id": "20000000-0000-4000-8000-000000000003",
          "text": "Virus"
        },
        {
          "id": "20000000-0000-4000-8000-000000000004",
          "text": "None"
        }
      ],
      "correctOptionIds": ["20000000-0000-4000-8000-000000000001"],
      "durationSeconds": 20
    }
  ],
  "createdAt": "2026-10-24T00:00:00.000Z",
  "updatedAt": "2026-10-24T00:01:00.000Z",
  "hostable": true,
  "errors": []
}
```

Every question requires `id`, `type`, `prompt`, `options`, `correctOptionIds`, and `durationSeconds`; every option requires `id` and `text`. There are no implicit defaults on PUT. Use `""`, `[]`, and `null` duration to represent incomplete fields. To clear all content, send `{ "title": "", "questions": [] }`; the response has the same readiness errors as the empty creation example.

Generate each question and option UUID on the client when adding it. Reuse it when editing or moving that item. Question IDs must be unique within a quiz; option IDs must be unique within their question. UUID uniqueness and reference comparisons are case-insensitive; submitted strings are preserved. IDs are scoped to this aggregate, not references to another quiz's content. Correct-option IDs must be unique and reference options in the same question. Dangling references and duplicates are malformed structure (400). Zero or several distinct correct choices are valid incomplete drafts (200, not hostable).

Array position explicitly defines both question and option order; there is no separate `order` property or reorder endpoint. For a saved collection `[A, B]`, submit the full question objects as `[B, A]` in the next PUT. GET returns `[B, A]` with the same identities and correct-option mappings. Reordering options likewise preserves answer identity because correctness references option IDs rather than array positions.

### Structural bounds versus readiness

| Field                           | Save structure (400 on violation)                                     | Hostable content (200 with errors when incomplete) |
| ------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------- |
| `title`                         | Required string, at most 200 characters                               | Nonempty after trimming                            |
| `questions`                     | Required array, 0–20 question objects                                 | 1–20 questions                                     |
| `questions[i].id`               | Required UUID, unique within quiz                                     | Same structural rule                               |
| `questions[i].type`             | `multiple-choice` only at this stage                                  | Same structural rule                               |
| `questions[i].prompt`           | Required string, at most 2000 characters                              | Nonempty after trimming                            |
| `questions[i].options`          | Required array, 0–4 option objects                                    | Exactly four                                       |
| `questions[i].options[j].id`    | Required UUID, unique within question                                 | Same structural rule                               |
| `questions[i].options[j].text`  | Required string, at most 1000 characters                              | Nonempty after trimming                            |
| `questions[i].correctOptionIds` | Required array, 0–4 unique UUIDs referring to this question's options | Exactly one                                        |
| `questions[i].durationSeconds`  | Required `null` or integer from 0 to 3600                             | 10, 20, 30, or 60                                  |

Unknown properties, nested arrays instead of objects, missing fields, and invalid scalar types receive 400 before persistence. Text is preserved, including leading/trailing whitespace. The HTTP server's request-size limit also applies.

Readiness is recomputed on save/read/list and never stored. Error order is title, question count, then each question in saved order (prompt, option count, option text, correct count, duration). Fields use zero-based array positions. Codes are `REQUIRED`, `QUESTION_COUNT`, `OPTION_COUNT`, `CORRECT_OPTION_COUNT`, and `DURATION`. List summaries reflect the edited title, question count, timestamp, and hostability.

For example, submit the save request above with `durationSeconds: 15`. The API saves it with `hostable: false` and:

```json
[
  {
    "field": "questions[0].durationSeconds",
    "code": "DURATION",
    "message": "Duration must be 10, 20, 30, or 60 seconds"
  }
]
```

Malformed identity example: repeated question UUIDs receive `{ "statusCode": 400, "message": ["questions: duplicate question IDs"], "error": "Bad Request" }`. Foreign and missing quizzes share the existing 404 response. No admin bypass exists. Shape validation precedes the owner-scoped write, so malformed input may receive 400 regardless of whether the quiz exists.

## Reopen

`GET /quizzes/{id}` returns HTTP 200 with the same detail shape, including saved title, questions, timestamps, and freshly derived readiness. `{id}` must be a UUID. The quiz must belong to the authenticated account. Persistence is independent of the application instance.

## List

`GET /quizzes` returns HTTP 200 with an array of owned summaries, ordered by `createdAt` descending, then UUID descending to break ties. There is no pagination in this slice. An account without quizzes receives `[]`.

```json
[
  {
    "id": "d65ae15c-a1d9-42ce-a328-104d2eebd8f1",
    "title": "",
    "questionCount": 0,
    "createdAt": "2026-10-24T00:00:00.000Z",
    "updatedAt": "2026-10-24T00:00:00.000Z",
    "hostable": false
  }
]
```

Summaries omit question contents and field errors. Reopen a draft to obtain its details.

## Errors

| Status | Trigger                                                      | Example body                                                                                                              |
| ------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 401    | Missing, invalid, expired, or revoked bearer credential      | `{ "statusCode": 401, "message": "Unauthorized", "error": "Unauthorized" }`                                               |
| 404    | Missing quiz or another owner's quiz, including for an admin | `{ "statusCode": 404, "message": "Quiz not found", "error": "Not Found" }`                                                |
| 400    | Unknown create property such as `ownerId`                    | `{ "statusCode": 400, "message": ["property ownerId should not exist"], "error": "Bad Request" }`                         |
| 400    | Invalid UUID path                                            | `{ "statusCode": 400, "message": "Validation failed (uuid is expected)", "error": "Bad Request" }`                        |
| 400    | Empty array request body                                     | `{ "statusCode": 400, "message": "Draft body must be a JSON object", "error": "Bad Request" }`                            |
| 400    | Invalid title                                                | Validation message array, for example `title must be a string` or `title must be shorter than or equal to 200 characters` |

Invalid create requests add no quiz. Invalid or unauthorized saves leave the entire saved aggregate, including timestamps, unchanged. All credentials failures use the existing auth contract. Missing and foreign UUIDs deliberately share the same response.

## OpenAPI and UI handoff

In nonproduction, `/api` shows the Swagger operations and `/api-json` serves the generated document. The document includes bearer authentication, create input examples, nested question/option schemas, hostable/incomplete/empty save examples, list summaries, and 400/401/404 examples. Integration tests compare generated success/error examples with actual HTTP responses, normalizing only generated IDs and timestamps.

The separate UI can create, list, reopen, edit, and reorder drafts using this contract. Generate question/option UUIDs once, retain them across edits, display field errors using the returned array positions, and send the full content on each PUT. Delete controls depend on #49. This document is the contract handoff artifact; no external UI repository or maintainer was messaged. Token storage, rendering, and reauthentication interaction remain that repository's responsibility.

## Database rollout and verification

Apply migration `20261024T000000-add-quizzes` with `pnpm run db:migrate` against the intended deployment database before enabling the new application version. It adds `quizzes` with UUID identity, owner foreign key, title, ordered questions JSONB, UTC timestamps, and an owner/list-order index. Account deletion is restricted while quizzes reference the account; no cascading deletion of saved content is introduced.

Issue #48 uses the existing JSONB column and requires no new migration. Roll back only to a version capable of reading nonempty question aggregates, or disable quiz reads while reverting; the earlier #47 code modeled questions as empty and is not a compatible reader of edited quizzes. Retain saved data. The migration's down function drops the quiz table and must only be used on an empty/test database or after a separate confirmed data plan.

The quiz HTTP suite requires an explicitly configured database whose name ends in `_test`. Set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, and a test-only `JWT_SECRET` before running:

```sh
pnpm run db:migrate
pnpm run test:integration --runInBand quiz.controller.spec.ts
```

Verification uses PostgreSQL with real migrations and the real authentication stack, with normal-bootstrap-equivalent validation installed before route initialization. Most examples roll back after each behavior. The independent-instance check commits an edited quiz with a question, opens it through a second app/database pool, and explicitly removes its test records afterward. Do not run these database commands with production credentials.
