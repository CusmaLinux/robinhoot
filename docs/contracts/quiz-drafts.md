# Private quiz drafts

Issue [#47](https://github.com/CusmaLinux/robinhoot/issues/47), OpenSpec `add-quiz-authoring` tasks 2.1–2.3. This is the create/list/read slice. Question editing, ordering, full question readiness, and deletion remain in [#48](https://github.com/CusmaLinux/robinhoot/issues/48) and [#49](https://github.com/CusmaLinux/robinhoot/issues/49).

## Authentication and ownership

All three routes require `Authorization: Bearer <accessToken>` from the existing [account API](authentication.md). Credentials expire after fifteen minutes and remain subject to account/token-version checks. No additional role is required. Ownership comes exclusively from the verified identity; an admin receives no access to another owner's quiz.

No request accepts `ownerId`, account roles, IDs, timestamps, readiness, or questions. Unknown fields receive 400 rather than being silently ignored. Responses exclude owner identity and account details.

## Create

`POST /quizzes` accepts an optional JSON object. `{}` (or an omitted body) creates an empty draft. The only supported property is `title`, an optional string of at most 200 characters. `null`, nonstrings, and longer titles receive 400. Blank and whitespace-only titles are valid saved drafts but are not ready to host. Text is preserved as submitted.

```json
{}
```

HTTP 201:

```json
{
  "id": "d65ae15c-a1d9-42ce-a328-104d2eebd8f1",
  "title": "",
  "questions": [],
  "createdAt": "2026-10-24T00:00:00.000Z",
  "updatedAt": "2026-10-24T00:00:00.000Z",
  "hostable": false,
  "errors": [
    { "field": "title", "code": "REQUIRED", "message": "Title is required" },
    { "field": "questions", "code": "QUESTION_COUNT", "message": "Quiz must contain 1–20 questions" }
  ]
}
```

Alternatively, send `{ "title": "Biology" }`. The saved response has that title and only the `questions` readiness error. Every draft created by this slice starts with zero questions, so `hostable` is false. Readiness errors describe incomplete saved content, not a failed save. A readiness check does not return 400 or prevent persistence.

IDs are generated by PostgreSQL. Timestamps are UTC ISO 8601 strings and are equal at creation. A create response is sent only after insertion succeeds. Repeating POST creates another draft; it is not an idempotent update.

## Reopen

`GET /quizzes/{id}` returns HTTP 200 with the same detail shape, including saved title, questions, timestamps, and freshly derived readiness. `{id}` must be a UUID. The quiz must belong to the authenticated account. Persistence is independent of the application instance.

## List

`GET /quizzes` returns HTTP 200 with an array of owned summaries, ordered by `createdAt` descending, then UUID descending to break ties. There is no pagination in this slice. An account without quizzes receives `[]`.

```json
[
  {
    "id": "d65ae15c-a1d9-42ce-a328-104d2eebd8f1",
    "title": "",
    "questionCount": 0,
    "createdAt": "2026-10-24T00:00:00.000Z",
    "updatedAt": "2026-10-24T00:00:00.000Z",
    "hostable": false
  }
]
```

Summaries omit question contents and field errors. Reopen a draft to obtain its details.

## Errors

| Status | Trigger | Example body |
| --- | --- | --- |
| 401 | Missing, invalid, expired, or revoked bearer credential | `{ "statusCode": 401, "message": "Unauthorized", "error": "Unauthorized" }` |
| 404 | Missing quiz or another owner's quiz, including for an admin | `{ "statusCode": 404, "message": "Quiz not found", "error": "Not Found" }` |
| 400 | Unknown create property such as `ownerId` | `{ "statusCode": 400, "message": ["property ownerId should not exist"], "error": "Bad Request" }` |
| 400 | Invalid UUID path | `{ "statusCode": 400, "message": "Validation failed (uuid is expected)", "error": "Bad Request" }` |
| 400 | Empty array request body | `{ "statusCode": 400, "message": "Draft body must be a JSON object", "error": "Bad Request" }` |
| 400 | Invalid title | Validation message array, for example `title must be a string` or `title must be shorter than or equal to 200 characters` |

Invalid create requests add no quiz. All credentials failures use the existing auth contract. Missing and foreign UUIDs deliberately share the same response.

## OpenAPI and UI handoff

In nonproduction, `/api` shows the Swagger operations and `/api-json` serves the generated document. The document includes bearer authentication, create input examples, response schemas, readiness examples, list summaries, and 400/401/404 examples. Integration tests compare generated success/error examples with actual HTTP responses, normalizing only generated IDs and timestamps.

The separate UI can create a draft, list owned summaries, and reopen it using this contract. Its editor/save/reorder/delete controls depend on subsequent API slices. This document is the contract handoff artifact; no external UI repository or maintainer was messaged. Token storage, rendering, and reauthentication interaction remain that repository's responsibility.

## Database rollout and verification

Apply migration `20261024T000000-add-quizzes` with `pnpm run db:migrate` against the intended deployment database before enabling the new application version. It adds `quizzes` with UUID identity, owner foreign key, title, ordered questions JSONB, UTC timestamps, and an owner/list-order index. Account deletion is restricted while quizzes reference the account; no cascading deletion of saved content is introduced.

Rollback the application routes while retaining saved data. The migration's down function drops the quiz table and must only be used on an empty/test database or after a separate confirmed data plan.

The quiz HTTP suite requires an explicitly configured database whose name ends in `_test`. Set `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, and a test-only `JWT_SECRET` before running:

```sh
pnpm run db:migrate
pnpm run test:integration --runInBand quiz.controller.spec.ts
```

Verification uses PostgreSQL with real migrations and the real authentication stack, with normal-bootstrap-equivalent validation installed before route initialization. Most examples roll back after each behavior. The independent-instance check commits a draft, opens it through a second app/database pool, and explicitly removes its test records afterward. Do not run these database commands with production credentials.

The 27 quiz HTTP behaviors pass; the full integration suite passes 40 tests across three suites. The existing unit suite passes 56 tests and e2e passes four.
